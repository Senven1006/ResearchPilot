# 1. 项目概述

## 1.1 项目背景

科研人员日常面对的核心工作可以概括成三件事：把论文读懂、把结论核实、把想法写成论文。现有工具把这三件事拆散在不同软件里——PDF 阅读器负责看、笔记软件负责记、通用大模型负责"聊"，而三者的上下文互不相通。由此产生三个具体痛点：

- **结构与证据丢失**：PDF 是排版格式而非语义格式，复制出来的正文会丢掉标题层级、表格行列、图表编号与公式，导致"看过"却"查不到"。
- **幻觉代价高**：通用大模型可以流畅地编造实验设置、作者机构与参考文献；科研场景下这类错误无法容忍。
- **链路断裂**：检索到的证据无法回溯到原文位置；阅读时的疑问无法直接变成写作素材；写作时的参考文献无法确认真实存在。

ResearchPilot 的定位是：**把一篇（或一批）PDF 变成可检索、可核对、可对照阅读、可复用的结构化知识**，并围绕它提供问答、对比、翻译与写作四类能力。

## 1.2 建设目标

| 目标 | 可度量的验收口径 |
|---|---|
| 结构化理解 | 单篇 15 页论文 2 秒内产出标题树、表格、图表、公式、参考文献与附录结构 |
| 抗幻觉问答 | 每条结论绑定"论文 + 页码 + 章节"锚点；断言级核验给出已核验/弱支持/未支持三态 |
| 多文推理 | 跨论文对比时每篇保底 2 条证据，并标注"仅一侧有据" |
| 版式阅读 | 标题树导航、表格/图表/公式分栏呈现、正文引用与文献双向跳转 |
| 翻译 | 划词翻译 2 秒级返回；按章节渐进翻译，读完一节再译下一节 |
| 写作辅助 | 由 idea 生成三段框架，参考文献只来自库内真实论文，越界引用可检出 |
| 可运行性 | 无 GPU、无本地模型环境（仅在线模型可用）也能跑通全流程 |

## 1.3 交付范围

| 交付物 | 内容 |
|---|---|
| 后端服务 | FastAPI 应用，8 个 Python 模块、5388 行代码（非空行）、26 个 HTTP 接口 |
| 前端应用 | React 19 + Vite 单页应用，3 个界面（问答 / 结构化阅读 / 写作 Copilot），2914 行代码 |
| 数据层 | ChromaDB 持久化向量库 + 本地文件缓存（原件留档、解析结果、图表裁图、译文、图表 SVG） |
| 质量保障 | 离线 pytest 套件（14 个接口级用例）+ GitHub Actions 双流水线（后端测试 / 前端构建与静态检查） |
| 工程文档 | README、环境变量模板、依赖清单、本技术文档 |

## 1.4 关键设计取舍

> 第一原则：**能给出出处就说，给不出就明确说不知道**。所有结论都绑定到可核查的证据锚点上，宁可弃答也不编造。

> 第二原则：**本地优先、渐进降级**。默认走本地模型，缺 Ollama 时自动改用在线模型与离线哈希嵌入，功能不中断，只在界面上标注当前后端与质量差异。

## 2.4 约束与假设

- 单机部署，无 GPU 假设成立；模型能力依赖 Ollama 或在线 API。
- 扫描件只做文字级 OCR，不还原表格与公式结构（版面分析需要额外模型）。
- 公式为近似 LaTeX（字体符号映射 + 上下标推断），不追求像素级排版还原。
- 无外部文献检索能力，因此"无幻觉参考文献"以"只允许引用库内论文"来保证。

# 3. 系统架构设计

## 3.1 总体架构

系统采用四层结构，自上而下依次是展示层、接口层、能力层、存储与模型层。层间只通过明确的函数签名或 HTTP 契约交互，能力层不直接依赖具体模型（嵌入函数以参数注入），因此可以整体替换模型而不改动业务代码。

```text
+------------------ Presentation: React 19 + Vite ------------------+
| QA (single / compare)   Reader (tree / table / figure / formula)  |
| Bilingual reader        Writing Copilot (outline / chart / trans) |
+-------------------------------+-----------------------------------+
                                | /api reverse proxy -> 127.0.0.1:8000
+-------------------------------v-----------------------------------+
| API layer: FastAPI (main.py, 26 routes)                           |
| token guard / CORS allowlist / validation / error mapping / paths |
+------+----------+----------+----------+----------+---------------+
       |          |          |          |          |
+------v-----+ +--v-------+ +v--------+ +v--------+ +v---------+
|pdf_structure| |embedding | |   qa    | |translat.| | writing  |
|parse/OCR    | |backend   | |retrieve | |translate| |outline   |
|1520 lines   | |137 lines | |611 lines| |215 lines| |215 lines |
+------+-----+ +--+-------+ +-+-------+ +-+-------+ +-+--------+
       |          |          |          |          |
+------v----------v----------v----------v----------v---------------+
| Storage & model layer                                            |
| ChromaDB: research_papers / paper_units (+ *_hash fallback sets) |
| File cache: data/parsed, figures, translated, charts             |
| Models: Ollama (nomic-embed-text / qwen2.5:7b) - DeepSeek API    |
| OCR: RapidOCR-onnxruntime (onnxruntime backend, no tesseract)    |
+------------------------------------------------------------------+
```

上图中各层职责与模块行数对应第 3.2 节；`_hash` 后缀是嵌入降级时使用的独立集合。

## 3.2 模块职责

| 模块 | 职责 | 关键导出 |
|---|---|---|
| `main.py` | 路由装配、参数校验、集合访问、模型路由 | `ask_paper` / `index_one_pdf` / `hybrid_retrieve` / `resolve_model` |
| `pdf_structure.py` | 版式感知解析、OCR、标题树、表格/图表/公式/文献/附录 | `StructureParser` |
| `embedding.py` | 嵌入后端探测与降级、哈希向量 | `detect` / `hash_embed` / `collection_suffix` |
| `qa.py` | 检索单元构建、BM25、RRF、证据配额、断言核验 | `build_units` / `verify_claims` |
| `semantic_dedup.py` | 句子级语义对齐、版本建议 | `compare_documents` / `build_recommendation` |
| `translation.py` | 分章节翻译、批量并发、磁盘缓存 | `translate_structure` / `translate_texts` |
| `writing.py` | 无幻觉框架、拓扑图脚本、学术翻译 | `build_outline_prompt` / `validate_citations` |
| `dataviz.py` | CSV 画像、SVG 图表、确定性图注 | `build_report` |

## 3.3 核心数据流

**入库（上传 → 可检索）**

```text
PDF -> page spans (font, size, bbox)
    -> scanned-page check (chars < 40 and image ratio > 50%) -> 200dpi render -> RapidOCR
    -> structure: TOC or font clustering -> heading tree; find_tables -> tables;
                  caption-based figure crop; math-font lines -> approx LaTeX;
                  references and appendix split into standalone sections
    -> dual write: 800-char paragraph chunks -> research_papers
                  anchored units (paragraph/table/figure/equation/reference/meta) -> paper_units
```

**问答（问题 → 带锚点的答案）**

```text
question -> hard terms (numbers / model ids / greek letters) + intent (table/formula/reference/meta)
         -> vector recall 40 + BM25 recall 40 -> RRF fusion
         -> re-weight: entity coverage, literal number hit, intent anchor,
            section-title overlap, reference penalty
         -> quota selection (compare mode: at least 2 per paper)
         -> evidence with anchors (paper / page / section / table or equation id)
         -> LLM answer -> claim split -> semantic support x number consistency -> 3-state verdict
```

## 3.4 存储设计

| 存储 | 内容 | 关键字段 |
|---|---|---|
| `research_papers` | 段落块（800 字/块，重叠 120） | filename、file_sha256、page、chunk_number、arxiv_id、version |
| `paper_units` | 结构化检索单元 | unit_id、anchor_type、anchor_label、section、section_level、page、ref、year、title |
| `*_hash` | 降级模式的两套同名集合 | 同上，维度 384（Ollama 为 768） |
| `data/parsed/*.json` | 完整解析结果（含 Markdown 版本） | meta、outline、sections、tables、figures、equations、references、appendix、stats、limitations |
| `data/papers/<sha256>.pdf` | 入库时的原件留档，供 `GET /papers/file/{sha256}` 取回 | 以内容哈希命名，天然去重；缺失不影响索引 |
| `data/figures/<sha>/` | 图表裁图 PNG | 按页与序号命名 |
| `data/translated/<sha>.<model>.json` | 段落级译文缓存 | 段落哈希 → 译文 |
| `data/charts/<stem>/` | 可视化 SVG | 折线/柱状/雷达 |

集合按嵌入后端隔离（`_hash` 后缀）是关键决策：不同后端的向量维度与语义空间都不兼容，混写会让检索彻底失真，而隔离后切换后端不需要重建另一侧的索引。

## 3.5 接口清单（26 个）

| 分组 | 路径 | 说明 |
|---|---|---|
| 基础 | `GET /`、`GET /health`、`GET /papers/status` | 健康检查、嵌入后端与库统计，并标记原件可下载 |
| 索引 | `POST /papers/index`、`POST /papers/batch-index` | 单篇 / 批量入库，`structure=true` 同步建单元并留档原件 |
| 原件 | `GET /papers/file/{sha256}` | 取回留档 PDF；sha256 需为 64 位十六进制，缺失返回 404 |
| 解析 | `POST /papers/parse`、`POST /papers/structure`、`GET /papers/structure/{id}`、`GET /papers/structure/{id}/figures/{name}` | 文本抽取、结构化解析、结果缓存、裁图 |
| 去重 | `POST /papers/duplicates/check-file`、`GET /papers/duplicates/check`、`POST /papers/duplicates/semantic-check` | 字节去重、版本识别、正文语义比对 |
| 问答 | `POST /papers/ask` | `mode=single\|compare`，返回证据/核验/覆盖率 |
| 翻译 | `POST /translate`、`POST /papers/structure/{id}/translate` | 划词、分章节（可选 `sections`） |
| 写作 | `POST /writing/outline`、`POST /writing/diagrams`、`POST /writing/translate` | 框架、拓扑图脚本、学术英文 |
| 可视化 | `POST /dataviz/report`、`GET /dataviz/charts/{stem}/{name}` | CSV 报告与 SVG 图表 |

## 3.6 部署拓扑

单机部署，三个进程：后端 `uvicorn main:app --port 8000`、前端 `vite`（开发 5173 / 生产静态托管）、Ollama `11434`（可选）。前端通过 `/api` 前缀代理到后端，避免跨域配置；数据全部落在仓库同级的 `data/` 目录，可直接打包迁移。

对外暴露时有两道可选加固，默认关闭以保持本机开发零配置：

- **令牌守卫**：一个 HTTP 中间件拦截除 `/`、`/health`、`/docs`、`/redoc`、`/openapi.json` 之外的请求，要求 `X-API-Token` 头或 `?token=` 参数，用 `secrets.compare_digest` 恒时比较。前端在 `src/api.js` 里统一注入请求头，`<img src>` 类请求（裁图、SVG 图表）走查询参数。
- **CORS 白名单**：`ALLOW_ORIGINS` 逗号分隔，默认只放行 5173。

这两项解决的是"本机/内网自用"场景，不构成多租户隔离——token 会进入浏览器 bundle 与 URL，公网部署仍需 HTTPS 反代与账号体系。

# 4. AI 技术方案

## 4.1 任务与选型

| 子任务 | 选用方案 | 选型理由 | 放弃的备选 |
|---|---|---|---|
| 结构抽取 | PyMuPDF span 级 API | 单库同时提供字号/字体/坐标、`get_toc`、`find_tables`、图像与绘制信息，无需多库拼接 | pdfplumber（无 OCR）、pypdf（无版面）、Marker（依赖 torch 与模型下载） |
| 扫描件 OCR | RapidOCR-onnxruntime | 纯 pip 安装、自带 PP-OCR 模型、跑在 onnxruntime 上，不依赖系统 tesseract | Tesseract（需外部二进制）、PaddleOCR（依赖重）、云 OCR（隐私与费用） |
| 语义嵌入 | `nomic-embed-text`（Ollama） | 本地推理、768 维、中英混排表现稳定 | OpenAI embedding（需外网与费用）、句向量模型（需 torch） |
| 降级嵌入 | 自研哈希向量（384 维） | 零依赖、确定性、可离线；保证无 Ollama 时全链路可用 | 无（原先的方案是直接不可用） |
| 对话生成 | DeepSeek（在线）/ qwen2.5:7b（本地） | 在线模型质量高、成本低；本地模型可离线；两者通过统一接口切换 | 单一模型（任一不可用即中断） |
| 向量库 | ChromaDB 持久化 | 单文件部署、自带元数据过滤、支持 upsert 与集合隔离 | FAISS（无元数据过滤）、Milvus（需服务化） |
| 图表绘制 | 自研 SVG 生成 | 环境无法安装 matplotlib，SVG 无损放大、无第三方依赖、可文本检索 | matplotlib（pip 源不可得）、plotly（需前端运行） |
| 翻译 | 分章节 + 批量并发 + 缓存 | 输出 token 是瓶颈，按章节切分把等待时间降到可读级别 | 整篇一次性翻译（等待数分钟） |

## 4.2 集成方式

**模型与业务解耦。** 能力层不直接调用模型：`qa.verify_claims` 与 `semantic_dedup.compare_documents` 都接收一个异步 `embed_fn`，`translation` 接收 `generate`，由接口层注入。这样替换后端（Ollama ↔ 在线）不需要改算法代码，也让算法可离线单测。

**统一模型路由与降级链。**

```python
# resolve_model 的决策顺序
await embedding.detect()            # cached /api/tags probe (60s TTL)
if request == "local" and local_ready:      return "local"
if request == "local" and not local_ready:  return "deepseek" if key else 503
if request == "auto":                       return "deepseek" if key else ("local" if local_ready else 503)
```

**提示词把约束变成可验证项。** 生成阶段不只写"不要编造"，而是要求模型使用给定编号：问答用 `[证据 N]`，框架用 `[R1]..[Rn]`。生成后用正则校验编号集合，越界即标记（`validate_citations`），从而把"信任模型"换成"检查输出"。

**证据组装即锚点。** 每条证据在送入模型前已带上 `论文 / 章节 / 页码 / 表格或公式编号`，模型只需引用编号，位置信息由系统保证，避免模型自行描述页码时出错。

## 4.3 检索优化策略

| 策略 | 具体做法 | 实测效果 |
|---|---|---|
| 结构化单元替代定长切块 | 表格整表成块、文献逐条成块、段落按句边界切分 | "超参数 β1/β2" 从召不回变为第 1 位命中 |
| 单复数与中英术语映射 | `GPUs→gpu`；中文技术词映射英文（注意力→attention、显卡→GPU 等 40 余条） | 中文提问可命中英文正文 |
| 数字逐字命中加权 | 命中数字/型号 +0.35（归一化） | "28.4 BLEU""8 张 P100"稳定命中 |
| 实体覆盖率 | 点名实体一个都没出现时分数 ×0.55 | 避免"表2 概述"类泛化段落挤掉硬件段落 |
| 意图锚点 | 问表格/公式/文献时对应类型 ×1.12，问正文时文献 ×0.7 | 文献条目不再抢占正文证据位 |
| 章节标题重合 | 问题词与章节标题词重合时最多 ×1.2 | "注意力头"命中 3.2.2 节 |
| 实体强制入候选 | 含点名实体的单元强制进入候选集 | 防止被向量排名过滤掉 |
| RRF 融合 | 向量与 BM25 按名次融合（k=60） | 兼顾语义与字面 |

## 4.4 生成与核验优化

- **断言级核验**：把答案切句，逐句取所引证据，计算语义支持度（余弦）与数字一致性（数字必须出现在所引证据或其页码/章节锚点中），合成置信度并映射为三态。实测在 v1 论文上 GPU 类问题支持度 87.5%，伪造数字（"16 张 V100"）被判未支持。
- **降级模式只做能做的**：无语义嵌入时，跨语言语义相似度必然偏低，若沿用三态会把正确回答误判为编造。因此降级时只校验数字与引用编号，结论标"未核验"并说明原因。
- **失败不丢证据**：模型异常时接口仍返回 200 与完整证据，前端可继续核对原文。

## 4.5 性能与成本优化

| 优化 | 做法 | 数据 |
|---|---|---|
| OCR 提速 | 关闭方向分类器（`use_cls=False`），引擎进程级复用 | 单页 11.7s → 3.7s |
| 解析提速 | 只对扫描页 OCR；表格按页并集扫描 | 15 页 1.3–1.6s；120 页 11.1s |
| 翻译吞吐 | 批次 5 段 + 并发 4 + 失败 3 次退避重试 | 95 段从 101s 降至约 40s 量级 |
| 翻译等待感 | 按章节请求，读完一节再点"继续翻译" | 单节 13–27s 可读，而非整篇数分钟 |
| 缓存 | 段落哈希缓存（按文档 + 模型隔离） | 二次打开 0 次模型调用 |
| 成本 | `max_blocks` 上限、参考文献不翻译 | 整篇翻译 token 量下降约 35% |
| 降级可用 | 嵌入哈希 < 10ms/批（本地计算） | 无 Ollama 时索引 1.9s、问答 3.3s |

## 4.6 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 本地模型缺失 / Ollama 未启动 | 原设计下全链路不可用 | 嵌入降级 + 对话回落 + 界面标注 |
| 在线 API 限流或抖动 | 单次请求失败 | 3 次退避重试；失败仍返回证据；可切本地模型 |
| 表格抽取错行 | 表格数据不准 | 题注配对 + 超宽/稀疏过滤；界面标注置信度与限制 |
| 翻译等待过长 | 体验差 | 章节渐进 + 缓存 + 并发 |
| 版本空间混写 | 检索失真 | 集合按后端隔离（`_hash` 后缀） |
| 参考文献造假 | 学术风险 | 只允许引用库内论文，越界编号检出 |

# 5. 核心功能实现

## 5.1 文件管理与两级去重

上传入口支持单篇与批量（上限 20 篇），每篇先做三重校验：扩展名、`%PDF-` 魔数、体积（30 MB）。批量接口逐文件处理，单文件失败只记入 `results[].error`，不影响其余文件。

去重分两级：

- **字节级**：`sha256(content)` 写入元数据，命中即提示"内容完全相同的已有论文"。
- **语义级**：同名 arXiv 编号的不同版本（如 v1 与 v7）用正文比对。把两版正文切句、去重，先按规范化字符串精确配对，剩余句子再用嵌入做一对一贪心匹配（阈值 0.88），得到 matched / added / removed，相似度取 `2M/(N1+N2)`；再结合版本号先后给出保留建议。

实测（v7 与已入库 v1 对比）：相似度 90.0%，匹配 297 句（精确 198 + 语义 99），新增 46 句、删除 20 句，变化集中在第 1–12 页，最终建议为"保留 v7，并将 v1 标记为旧版本"（`relation=incoming_newer`）。

关键实现细节：`load_indexed_pages()` 从 800 字重叠分块**精确还原**每页正文——相邻分块只在开头重叠 `CHUNK_OVERLAP=120` 字符，按"最长重叠后缀"拼接即可，不需要额外存原文快照。

## 5.2 版式感知的结构化解析

**标题树**：优先使用 PDF 书签（`get_toc`）；无书签时用字号加权中位数估出正文字号，以"字号 ≥ 1.12 倍正文""加粗且不小于正文"或"编号前缀"作为候选，按字号排名与编号点分深度（`1` / `1.1` / `1.1.1`）定级。TOC 标题的定位方式是在其所在页**按标题文本匹配**块位置（归一化后前缀匹配），再强制位置单调递增——这一改动修掉了"同一页多个章节时后续节拿到 0 段"的结构性缺陷。

**表格**：`find_tables()` 抽取后做合理性过滤（列数 > 25、非空单元格比例 < 0.3 视为误判），题注按"优先上方、水平有交集、距离 ≤ 160pt"配对，输出 Markdown 与二维数组两种形态。

**图表**：优先取 `get_image_info()` 中的位图，面积小于整页 3% 忽略、大于 85% 视为扫描底图忽略；矢量图无语义图像时，按图注上方的版面区域截图。裁图按 150 dpi 存 PNG 并通过 `/papers/structure/{id}/figures/{name}` 提供。

**公式**：识别数学字体（CMMI/CMSY/Symbol/MTMI 等）行，用 `math_ratio` 与运算符存在性判定，再按字符映射希腊字母与常见算子，按字号比例与基线偏移还原上下标，输出近似 LaTeX 与原始文本双栏，并给出置信度。

**参考文献**：先找标题型 References；无书签时按版面匹配，并从"最后一节"按连续文献条目特征切出独立章节，避免章节被文末内容吞掉（修复前 v1 的"7 Conclusion"含 368 段，修复后 6 段）。

**OCR**：扫描页渲染 200 dpi，RapidOCR 返回的四点框换算回 PDF 坐标，按行距聚合成段落；单次默认最多 20 页，超出部分在 `limitations` 中说明。

## 5.3 抗幻觉问答

**锚点单元**（`qa.build_units`）。每个检索单元带 `anchor_type`（段落/表格/图表/公式/参考文献/元信息）、`section`、`page`、`ref`、`year`。表格单元包含题注与整表 Markdown，文献单元为单条条目，元信息单元把"标题/作者/机构"打包成一个单元——这样"作者与机构是谁"能直接命中，而不是被正文段落淹没。

**混合检索**（`hybrid_retrieve`）。向量召回 40 条 + BM25 召回 40 条（词袋含中文二元组与中英术语映射），RRF 融合后按 4.3 节的加权规则重排，再按配额选取证据。所有通道都在同一候选池上打分，避免"先截断后加权"导致强信号被丢。

**证据与作答**。证据格式固定为 `[证据 N] 论文｜文件｜位置（类型·章节·编号）｜第 X 页` + 原文，提示词要求逐句标注编号、数字必须与原文一致、位置由系统给出。

**断言核验**（`verify_claims`）。切句后逐句取所引证据，计算语义支持度（余弦 ÷ 0.62 归一）与数字一致性（数字需出现在证据文本或其页码/章节锚点中），置信度 = 0.65 × 语义 + 0.35 × 数字通过，映射为已核验 / 弱支持 / 未支持 / 无引用；无嵌入后端时切到 `numeric_only` 模式，输出"未核验"而不是误判。

## 5.4 多文对比推理

对比模式（`mode=compare`）对每篇论文设置配额 `max(2, top_k // 篇数)`，先按配额填充再按总分补足，保证两侧都有证据。提示词要求输出"维度 × 论文"的 Markdown 对照表，每格标注证据编号，单侧缺失时写"仅一侧有据/无证据"。响应额外给出 `coverage`（每篇证据条数），前端据此显示证据分布。

## 5.5 版式阅读与双向跳转

结构化面板把解析结果分五栏呈现：标题树与正文、表格、图表、公式、参考文献。正文中的 `[12]`、`[3, 4]`、`[12–14]` 会被渲染成可点击标签：点击跳到参考文献并高亮该条；文献条目反向显示"被引 N 次 · 跳回：第 X 页"，点击回到第一个引用它的正文块。反向索引在前端由正文标记实时构建（`Map<编号, 引用位置[]>`），不额外占存储。

## 5.6 翻译与中英对照

**划词翻译**：`POST /translate` 单段翻译，进程内缓存最近 400 条，实测 2.0 秒返回，重复划同一句 0 秒。

**按章节渐进翻译**：前端打开对照时只请求当前章节（`sections=sec-N`，`max_blocks=20`），读完后点"继续翻译"译下一节；也可"一次译完"按块数预算（≤18 段/组）逐组推进。后端批次 5 段、并发 4、失败 3 次退避；译文按"文档 sha + 模型 + 段落哈希"落盘，二次打开零调用。

**保留原文的部分**：公式、表格、图表、参考文献不翻译；译文保留 `[n]` 标记以支持跳转。提示词明确要求模型名、数据集名、指标名、符号与数字保持英文。

## 5.7 写作 Copilot

**无幻觉框架**：先检索与 idea 相关的库内论文，把每篇的标题/作者/年份/文件/页码组装成 `[R1]..[Rn]` 白名单，再让模型只引用这些编号，最后用正则校验越界与非法格式（如 `[1]`）。库内没有论文时直接返回 400，而不是生成一段没有依据的文字。

**拓扑图脚本**：一次生成 Mermaid / Graphviz / TikZ / Matplotlib 四份脚本，做静态校验（首行图类型、括号配对、`tikzpicture` 环境、Python `compile`），逐份给出 `valid` 与 `issues`。

**学术翻译**：中→英学术语域，长文本按 3000 字符分块并发，失败重试，公式与指标名保留。

## 5.8 数据可视化与图注

`dataviz.build_report` 依次完成：解析 CSV（自动识别 UTF-8/GBK 等编码）→ 列画像（数值/类别/文本，含缺失、唯一值、min/max/mean/median/std）→ 统计表（Markdown + HTML）→ 图表 → 图注。

图表用纯 Python 生成 SVG：折线（含面积填充与网格）、柱状（含数值标签）、三维雷达（斜投影分层 + 半透明多边形）。**图注由统计量确定性生成**：折线给出首末值与相对变化、最陡区间、峰值位置；柱状给出最高/最低与极差占均值比例；雷达给出各指标归一化最大值及解读提示。这样做的好处是图注不可能出现"说上升但数据下降"的幻觉。

| 限制 | 说明 | 影响面 |

| 扫描件的表格与公式 | 只做文字 OCR，不还原结构 | 扫描版论文的表格数据需人工核对 |

| 鉴权强度 | 单令牌 + CORS 白名单，token 会进 bundle 与 URL | 适合单机/内网自用，非多租户方案 |

# 7. 创新点

## 7.1 技术创新点

1. **结构化锚点检索（Anchor-Aware RAG）**：不把整篇论文当无结构长文本，而是把表格、图表、公式、文献条目、元信息分别建成立检索单元并携带位置锚点。检索命中即得到"第几页、哪一节、哪张表"，把定位从"模型描述"变成"系统给定"。
2. **断言级抗幻觉核验**：在生成之后再做一次可计算的检查——逐句取所引证据，计算语义支持度与数字一致性，输出三态结论。配合"引用编号白名单 + 越界正则校验"，把抗幻觉从提示词层面推进到可度量的工程层面。
3. **无 Ollama 环境下的自动降级**：以可插拔嵌入后端（Ollama 语义嵌入 / 内置 384 维哈希嵌入）加集合隔离，实现"缺本地模型也能运行"；并在降级时自动切换核验模式，避免把正确回答误判为编造。
4. **分块精确还原原文**：利用"定长切块 + 固定重叠"的可逆性，用"最长重叠后缀"拼接从向量库精确还原每页正文，使语义比对与原文核对不需要额外存储原文快照。
5. **无监督的版面结构推断**：在无书签 PDF 上，用字号加权中位数、编号点分深度、标题文本定位与位置单调性约束组合推断标题树，并单独切分参考文献章节，解决了"章节吞并文末内容"的常见错误。
6. **确定性图注生成**：图注由统计量（斜率、极差、最陡区间、峰值）直接生成，绕开大模型，从机制上排除"图注与数据不符"的幻觉。

## 7.2 应用创新点

1. **阅读—查证—写作闭环**：同一份结构化解析结果同时服务于阅读导航、抗幻觉问答、跨文献对比、翻译与写作框架，避免在多个工具间反复搬运上下文。
2. **按章节渐进翻译的阅读节奏**：把"等整篇翻译"改为"读一节、译一节"，把不可控的分钟级等待拆成可接受的十秒级等待，并提供"一次译完"作为备选。
3. **正文引用与文献条目的双向无损跳转**：从 `[12]` 跳到文献、从文献跳回被引位置，形成可正反追溯的阅读路径，而非单向参考列表。
4. **对比模式的双侧证据保障**：通过每篇保底配额与"仅一侧有据"标注，把跨文献对比从"模型自由发挥"约束为"有据可比、无据明说"。
5. **面向评审与教学的可解释性**：界面同时展示证据锚点、核验结论、解析限制与当前模型后端，使用者能一眼判断"这条结论是怎么来的、可信到什么程度"。

## 7.3 工程实践创新点

1. **离线可测的 AI 系统**：多数 RAG 项目"只能在有模型、有网络时验证"，本项目的测试套件通过"关端口强制降级 + 桩函数替换模型调用 + 现场合成 PDF"三件事，把整条 AI 链路变成可在 CI 里 3 秒跑完的确定性用例。
2. **降级路径本身被测试覆盖**：降级不是兜底文档里的一句话，而是有用例断言的具体行为（后端标识 `hash`、集合带 `_hash` 后缀、核验模式自动切换、`grounding.score` 置空）。
3. **原件留档与内容哈希对齐**：以 `sha256(内容)` 同时作为去重键、留档文件名与下载路由参数，三处共用同一标识，避免"索引说 A、文件是 B"的漂移。
4. **安全开关零成本**：鉴权与 CORS 走环境变量，未配置时行为与本机开发完全一致，配置后即刻生效，不需要改代码分支。
5. **失败可见而非静默兜底**：降级、留档失败、单元清理失败、译文命中缓存这类"没出事但状态变了"的情况一律在响应里给出布尔值或计数，界面据此显示，而不是悄悄替换结果。

# 8. 总结与展望

## 8.1 总结

ResearchPilot 已完成从 PDF 到可核对知识的完整链路：结构化解析解决"看得懂结构"，锚点检索解决"找得到证据"，断言核验解决"敢不敢相信"，翻译与双栏对照解决"读得下去"，写作 Copilot 与数据可视化解决"用得上"。工程上以 5388 行后端与 2914 行前端实现 26 个接口与 3 个界面，在无 GPU、无本地模型的环境下仍可完整运行，并在真实论文上完成了端到端回归；同时以 14 个离线接口用例 + CI 双流水线把回归固化为可重复执行的流程。

过程中也暴露出若干真实问题并已修复：文末参考文献被并入最后一节、同页多章节的后续节为空、降级模式下核验误判、翻译等待过长、图表页无法滚动等。这些问题构成了后续版本的回归用例。
