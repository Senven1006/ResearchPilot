# gold set 评测报告（Recall@K 与引用准确率）

> 目的：把"检索是否找得到、引用是否落对页"从单点演示变成可复现的数字。
> 所有数字由 `eval/run_eval.py` 在真实语料上跑出，原始输出见 `eval/last_run.json`。

## 1. 语料与 gold set

| 项 | 内容 |
|---|---|
| 语料 | 21 篇 arXiv 论文（2013–2017，NMT / 注意力 / 归一化 / 子词 / 大规模训练方向），4779 个检索单元 |
| gold set | **36 题**，每篇 1–5 题，覆盖 19 篇论文 |
| 嵌入后端 | 内置哈希嵌入（384 维，降级模式；本机无 Ollama） |
| 金标页怎么来 | 每题给出一个 `keyword`（如 `P100`、`heads`、`BLEU`），脚本在该论文的检索单元里定位所有命中页作为金标页集合；匹配不到的题会被标 `unverifiable` 并剔除 |
| 剔除情况 | 初始 36 题全部可核验（曾因语料缺 Attention 原文剔除 5 题、因关键词不存在换 1 题，均已修正后重跑） |

金标页由关键词定位而不是手填，好处是不会出现"答案对不上但页号写错"的假分数；代价是当关键词在论文里多次出现时，金标页会变成一个较宽的集合（q18 的关键词几乎遍布 1–9 页），这会**高估**召回。

## 2. 指标定义

| 指标 | 定义 |
|---|---|
| Recall@K | 前 K 条证据里，存在页码落在金标页集合（或文本命中关键词）的题所占比例 |
| MRR | 第一条命中证据名次的倒数求均值 |
| 引用有效性 | 答案里每个 `[证据 N]` 都在证据条数范围内（不越界、不造号） |
| 引用落点准确率（按题） | 至少一条被引证据的页码落在金标页集合的题所占比例 |
| 引用精度（按引用） | 所有被引证据中页码落在金标页的比例（77/102 = 0.755） |
| 核验支持率 | 断言核验里判为 supported/weak 的比例；**降级模式不适用**（见 §4） |

## 3. 结果

| 指标 | 数值 |
|---|---|
| Recall@1 | **0.722**（26/36） |
| Recall@3 | **0.889**（32/36） |
| Recall@5 | **0.972**（35/36） |
| MRR | **0.822** |
| 回答成功率（DeepSeek 生成） | 36/36 |
| 引用有效性 | **1.000**（102 条引用全部在范围内，无越界编号） |
| 引用落点准确率（按题） | **0.722**（26/36） |
| 引用精度（按引用） | **0.755**（77/102） |
| 核验模式 | `numeric_only`（无 Ollama → 只做数字/引用核验） |
| 核验分布 | unverified 75、no_citation 53、weak 3 |

## 4. 两个必须说明的口径问题

1. **`supported_rate` 在降级模式下没有意义。** 哈希嵌入没有语义空间，`verify_claims` 会切到 `numeric_only`，把断言标成 `unverified`（这是"降级不误判"的设计，不是缺陷）。因此本报告不把 `supported_rate`（0.023）当作质量指标；要测得它需要启动 Ollama 的 `nomic-embed-text` 后重跑。
2. **召回被关键词定位"放宽"了。** 关键词在论文里出现得越多，金标页集合越大，命中越容易。q18/q31 这类题的金标页很宽，因此 Recall 数字偏乐观；把金标改成"单页 + 精确答案片段"会让数字下降，但更严格。

## 5. 失败案例分析

**检索未进 Top1 的 10 题**（多为"问概念而非问数字"）：

| 题 | 首次命中名次 | 金标页 | 实际取到的页 |
|---|---|---|---|
| q02 注意力头数 h | 3 | 5,7,9,10,13,14,15 | 4,4,5,5,8 |
| q09 模型名 RNNsearch | 4 | 5–9,13–15 | 4,11,3,5,5 |
| q16 位置编码（ConvS2S） | **未命中** | 2,7,8,9,14 | 1,6,10,6,5 |
| q31 困惑度 | 4 | 1,2,5,6,7,8 | 10,10,10,1,1 |
| q36 架构对比 | 4 | 1,2,3,4,7,8 | 5,5,6,2,5 |

- **q16 是唯一在 K=5 内完全没命中的题**：问题问"如何编码位置信息"，但论文里的表述是 position embeddings 与卷积堆叠，哈希嵌入只能匹配字面词，把注意力放到了别的高频页。
- **q02/q09 的共性问题**：问"名字/数量"时，答案常出现在表格或配置段落，而这些段落与问题措辞的字面重合度低；这也是 @1 只有 0.722 的主要原因。

**引用落点错误的 10 题**：模型倾向引用同一页的 2–4 条证据（如 q36 连续引用第 5 页 4 次），而金标页分散在 1–8 页。说明模型作答"自洽但不深入"——它引用了检索给它的证据，问题在检索没把金标页放在前面，而不是模型造号（引用有效性 1.000 佐证了这一点）。

## 6. 局限

- **单语料、单领域**：21 篇 NLP/注意力论文，不能外推到其他学科；
- **降级嵌入**：哈希嵌入的召回明显弱于语义嵌入，上述数字是"最差配置"下的下限；
- **页码粒度**：只要页码命中就算对，没有校验"具体句子是否支持答案"；
- **关键词定页**：宽关键词会放宽召回（见 §4）；
- **未覆盖跨论文问题**：36 题都是单篇内提问，跨文献对比、图谱问答未纳入本轮指标。
